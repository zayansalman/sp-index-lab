# Proof Hardening (Tier A) — Design Spec

**Date:** 2026-07-26
**Branch:** `feat/proof-hardening` (from `main` after PR #87 merges; rebase over the
concurrent design-token work before starting)
**Goal:** Convert the project's one provable claim — a handful of names reproduces the
S&P 500 — into its strongest, honest form, at **zero statistical cost**: no new trials, no
registry writes, no pre-registration, no change to any strategy. Every deliverable is
descriptive analytics, exports, copy, or tests.

## Why (context that must survive into implementation)

1. The shipped 95.2% R² is an **in-sample ceiling**: hindsight OLS with sign-unconstrained
   coefficients (`src/proof/concentration.py:206`), not an investable portfolio. The site
   reads it as an investable result. Nothing currently published measures how well an
   *implementable* basket tracks.
2. The research path **cannot express** a replication objective:
   `src/research/scoring.py:109,121,124` call `compute_performance_metrics` without
   `benchmark_nav`, so TE/IR/beta/alpha never compute in any trial; `beats`
   (`scoring.py:127-129`) is two absolute-return tests. Replication and active claims are
   conflated repo-wide.
3. LASSO is **provably inert** under long-only + fully-invested (‖w‖₁ ≡ 1; Brodie et al.
   PNAS 2009 eq. 5; verified numerically: max|Δw| = 6.6e-04 across λ ∈ [0, 100]). The
   working formulation is **cardinality-constrained simplex least squares** (two-pass:
   dense solve → top-k → re-solve). Probe (dev-only, 109 windows): OOS TE at k=20 ≈ 3.26%
   vs equal-20 3.80%, Mirror 5.85%, LASSO-two-stage 8.89% (0/109 wins).
4. Kremer, Lee, Bogdan & Paterlini (arXiv:1710.02435): nine constructions, S&P 500 stocks,
   2004–2016 — "no strategy is statistically significantly different from each other."
   External validation of this project's significance ceiling.
5. The elbow N-policy is a 4-parameter stopping rule, median N=11, never 20, pinned to the
   `SPN_MIN_STOCKS=10` floor 38.9% of 126 rebalances. Docs calling 20 "the natural
   breakpoint" or the elbow a "solved N" overclaim.

## Non-negotiable constraints

- **Zero registry cost.** Nothing in this spec runs through `run_experiment`, writes
  `data/research/*`, or emits a fitted performance metric (CAGR/Sharpe/excess return).
  Tracking error / replication R² of a *fixed, rule-defined* construction is descriptive.
- **No hardcoded numbers** in components, copy, or docs — all figures computed at export.
- **Baselines untouched.** SP-20 Mirror/Equal stay fixed at 20 (controls).
- **Frontend JSON ownership.** `frontend/public/data/*.json` is regenerated by the daily
  cron; local runs use `--out-dir` (added in `155b76f`) and are never committed.
- **Out of scope:** forward contract on the mandate candidate, breadth expansion, any raced
  strategy, the landing-page redesign itself (next project; consumes these exports).

## Deliverables

### A. Replication analytics

**A1. `rolling_replication_quality()`** in `src/proof/concentration.py`, sibling of
`rolling_concentration`.

- Inputs: adjusted price panel, benchmark series, N grid (reuse `[5,10,15,20,25,30,40,50]`),
  weighting ∈ {cap, equal}, PIT `universe_fn`, window/step (252/21, same as existing).
- Per window × N × weighting: build the *investable* basket exactly as `build_mirror_index`
  weights it (same drift/rebalance conventions — reuse its helpers, no reimplementation),
  compute daily active returns vs benchmark; report `tracking_error` (annualised) and
  `replication_r2 = 1 − TE²/σ_index²`.
- Aggregate mean/min/max per (N, weighting) + full window series for N=20.

**A2. Export block.** Extend `export_variance_decomposition()` (file currently has zero
frontend consumers) with a `replication` block:

```jsonc
{
  "replication": {
    "method": "pit_investable_baskets_252d_step21d",
    "ladder": {                       // the R² ladder, N=20
      "ols_ceiling": 0.952,           // existing r_squared_at_20 (hindsight OLS)
      "investable_cap": null,         // computed: cap-weighted top-20
      "investable_equal": null,       // computed: equal-weighted top-20
      "traded_strategies_note": "see performance_metrics tracking_error"
    },
    "by_n": [ { "n": 20, "weighting": "equal", "tracking_error": null,
                "replication_r2": null, "te_min": null, "te_max": null } ]
  }
}
```

**A3. Types + transform.** `frontend/lib/types.ts` + `useLabData.ts` transform for the new
block. The frontend has no test harness (lint + build only), so guard against the PR #84
failure mode (transforms silently dropping exported fields) with a dev-mode
`console.warn` when the raw JSON contains a `replication` block but the transform yields
`undefined`.

### B. Tracking-frontier exhibit (proof infrastructure)

**B1. `src/proof/replication.py`** (new; deliberately NOT `src/strategies/`).

- `simplex_ls_weights(returns, bench_returns, k)` — two-pass cardinality-constrained
  simplex least squares: (1) dense solve of min‖y − Xw‖² s.t. w ≥ 0, Σw = 1 (scipy SLSQP
  or cvxpy if already a dependency — check `pyproject.toml`; do not add heavy deps without
  need); (2) restrict to top-k weights, re-solve on the support.
- `tracking_frontier(prices, bench, k_grid, universe_fn)` — walk-forward *descriptive*
  evaluation: fit trailing 252d, measure next-21d realised TE; monthly steps; PIT universe
  (top-30 pool minimum; wider if cheap). Returns per-k: `te_oos`, `replication_r2_oos`,
  `mean_monthly_churn`, `max_weight`, `n_windows`.
- **Hard guard:** module computes ONLY tracking quantities. It must not import
  `compute_performance_metrics`, must not output CAGR/Sharpe/returns. Docstring states why
  (keeps the exhibit descriptive; a raced version would be Tier B with full pre-registration).

**B2. Export** `tracking_frontier` block (same JSON file as A2) for
k ∈ {10, 15, 20, 25, 30, 40}.

**B3. Runtime budget:** probe measured ~monthly-loop feasibility; keep full run under ~5 min
in the daily job; if slower, compute weekly grid or cache.

### D. Tests + carried-over exports

- **D1. L1-inertness regression test** (`tests/test_replication.py`): small long-only
  Σw=1 tracking problem; assert solutions at λ=0 and λ=100 identical within tolerance;
  docstring cites Brodie eq. 5 / Kremer et al. Prevents LASSO's reintroduction by assertion.
- **D2. Ceiling property test:** for each N: `replication_r2(investable) ≤ ols_r2 + ε`.
- **D3. Consistency test:** A1's TE for cap-20 over the full window ≈
  `performance_metrics.json → sp20_mirror.tracking_error` (same convention, tolerance).
- **D4. Guard test:** `src/proof/replication.py` exposes no return/Sharpe computation
  (import-level assertion or output-schema check).
- **D5. Solved-N series export** (carried from earlier decomposition, needed by the
  N-honesty copy and the future landing page): stamp `n_selected` through
  `dynamic_alpha` → `WalkForwardResult` → `run_alpha_backtest.py` persists
  `alpha_n_series` parquet → export `{series, mean, median, min, max, distribution,
  share_at_floor}`. Known hazard: weights are passed as a `pd.Series` whose `.attrs` do
  not reliably survive `pd.concat` (used by the cash overlay path) — stamp after the
  overlay call; the retained config is `overlay: "none"`, so it survives today, but add a
  test covering the overlay path. Then drive `ConcentrationChart`'s reference line from
  data (today `x={20}` hardcoded).
- **D6. Universe-rotation export** (carried from landing research): serialize
  `build_universe_schedule` (sole caller today: tests) → `universe_rotation.json`
  `{schedule, events, summary{distinct_tickers, entries, exits, avg_names_replaced_per_year,
  never_left[]}}`; ~26 KB, ~1 s compute. Framing rule: "the point-in-time universe this
  project trades" (proxy is 80–90% accurate vs true historical top-20 — never claim it IS
  the S&P's top 20).

## Sequencing

1. A (analytics + export) → 2. B (frontier) → 3. D (tests + exports) → 4. C (copy last —
it quotes A/B numbers). Single PR is acceptable; two PRs (A+B+D data layer, then C copy)
preferred if the diff grows.

## Error handling

- Missing parquet / short windows: skip gracefully with logged warning (match
  `export_frontend_data.py` conventions); frontend treats all new blocks as optional
  (same fallback pattern as `matched_window`).
- Solver failure in B: fall back to cap-ranked top-k equal-weight for that window and
  count fallbacks in the export (`n_fallback_windows`), mirroring `fallback_rate`.
